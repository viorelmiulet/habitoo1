- YouTube channel connections live in server-only `youtube_connections` (RLS, no client policies) with the refresh token encrypted by the portal credential cipher; access tokens are refreshed per call and `invalid_grant` sets status `expired`. Why: tokens never reach the browser or logs.
- Uploads are resumable: the server starts the session (with `Origin`), the browser PUTs the MP4 directly, with a server PUT fallback (≤100 MB); the server confirms the video via the API before marking `meta_posts` (`platform = 'youtube'`) published. Why: avoid worker body limits while never trusting client-supplied ids.
