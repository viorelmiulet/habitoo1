# Marketing feature pages

- Dedicated feature pages and their contents live in the browser-safe feature-pages registry; explicit section-to-slug mappings replace matching topics in the table of contents. Why: different URLs must not create duplicate features or leave section links behind.- Renamed feature-page slugs stay in `FEATURE_PAGE_ALIASES` and redirect permanently from the slug route. Why: already-shared or indexed addresses must keep working.

- Editorial contentModified drives visible dates, WebPage and sitemap; public cache lives in the existing server entry and excludes session HTML. Why: truthful dates and private-cache isolation.
- llms-full uses registries, shared FAQ, public aggregate statistics and reviewed Markdown extracted from public pages, excluding mock account previews. Why: complete public content only.
- IndexNow uses service-only revision receipts and a lock; the key file is served from the server entry (the key is public by protocol), static revisions are checked once per isolate and blog saves notify. Why: deduplicated batches without preview submissions.
- Blog article AEO (author organization, summary, TOC, JSON-LD, related, FAQ) lives in the pure blog-aeo module. Why: testable without rendering.
- Public offer addresses use the DB-generated immutable `properties.public_slug` (trigger, set at first publication, never copied by clones); UUID URLs 301 to it, eligibility/canonical/JSON-LD/sitemap live in `offer-seo.ts`, and offer IndexNow pings go through `seo_indexnow_offer_queue` drained by a cron route. Why: stable indexable URLs without blocking saves or publishing.
- Agency/agent public profiles use DB-generated immutable `organizations.public_slug`/`profiles.public_slug` (unique per agency; trigger `guard_public_slug_immutable` rejects changes, Settings only shows a read-only link) and security-definer RPCs sharing `public_offer_listable` (same rule as isOfferIndexable, copies listed via original); hidden agencies 404, inactive or empty profiles are noindex; sitemap/JSON-LD live in `agency-seo.ts` and offer changes enqueue profile URLs in `seo_indexnow_offer_queue`. Why: every visible agency gets a stable indexable profile without exposing private contacts.
- Agent public profiles can be hidden only by SuperAdmin via `profiles.public_profile_hidden` (trigger `guard_public_profile_hidden`, audited server function); the public profile RPCs, avatar path, sitemap and IndexNow profile trigger exclude hidden agents while their offers stay listed under the agency. Why: one database rule for every public surface without touching portal feeds.
