- Per-user Gmail connections keep the connector key (`lovack_*`) server-side only: encrypted with `APP_USER_CONNECTION_KEY_SECRET` into `public.app_user_connections` (RLS enabled, no policies, service_role grants only). Why: one agent's Gmail must never be readable by another agent or by the browser.
- The consent popup returns to the server endpoint `/api/oauth/google-mail/return`, which renders plain HTML and posts only the one-time `code` to the opener on the same origin; the authenticated `completeGmailConnect` server fn exchanges and stores the key. Why: the popup has no app session in the editor preview, and the key must never appear in a URL or the browser.
- The workspace Gmail (Habitoo's own address) is read only through the connector gateway inside `gmail-workspace.server.ts` with `LOVABLE_API_KEY` + `GOOGLE_MAIL_API_KEY`, and its status is exposed to SuperAdmin only. Why: those are workspace credentials, not agency data.
- Gmail consent asks for `userinfo.email`, `userinfo.profile`, `gmail.readonly` and `gmail.send` only. Why: reading the agent's inbox and sending from their own address is the whole feature; anything wider needs a new decision.
- The Google OAuth client must list `https://connector-gateway.lovable.dev/api/v1/app-users/oauth2/callback` as an authorized redirect URI; without it Google shows its own `redirect_uri_mismatch` page and no app code is at fault. Why: the gateway, not the app, is the only callback the provider sees.
