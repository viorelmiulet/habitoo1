- IMMOFLUX import uses API v2 only (`https://{subdomain}.immoflux.ro/api/v2/...?token=`, GET only through `immofluxGet`, token masked everywhere; subdomain stored as host `{sub}.immoflux.ro` with slug marker `api-v2`) and runs as per-agency `immoflux_import_jobs` in the development-clone worker; first import only (dedupe by org+source+external_id, existing rows and contacts never touched, nothing sent back), properties read per status via `filter_status__eq` 1–5 (resumable `status_step`, failed statuses reported, one unfiltered fallback only if all 5 fail), all statuses enter as drafts with no portal selections, mapped status/notes kept in internal notes, images via `property_import_images`. Why: agency isolation, read-only provider access and resumable background runs.
- IMMOFLUX jobs save after each created property and count resumed rows created by the same job as imported (one `imported` report row each, plus an agent row with email and reason); HTTP 429 (60 requests/min, ≥1.1 s spacing) pauses the job until the next cron tick without counting an error; `mode='repair'` jobs only queue images for properties with none and link a missing owner (`owner_contact_id IS NULL`), never touching other fields. Why: accurate counts after interruptions and safe backfills.
