- Meta (Facebook/Instagram) connections are server-only tables (`meta_*`, no client RLS policies) accessed via `src/lib/meta/*`; tokens encrypted with the portal credential cipher; state and `signed_request` are HMAC-verified in pure `core.ts`. Why: tokens never reach the browser or logs.
- Facebook page posting runs only server-side via `publishMetaPost` (`src/lib/meta/post.*`), history in server-only `meta_posts`; Graph error 190 sets the connection to `expired`. Page Reels validate actual MP4 metadata and use start/binary rupload/finish; persisted video IDs enable GET-only completion through the social-temp worker. Why: tokens stay private and processing never publishes twice.
- Instagram posting runs via `publishInstagramPost` (`src/lib/meta/instagram.*`) with the linked page's token; media are browser-prepared JPEG/MP4 uploaded server-side to private `social-temp` (tracked in `social_temp_files`, 1h signed URLs); history shares `meta_posts` with `platform`. Unfinished Reels and 24h cleanup are handled by the managed schedule `/api/public/cron/social-temp`, which exits early when idle. Why: tokens stay server-side and Meta needs fetchable URLs.
