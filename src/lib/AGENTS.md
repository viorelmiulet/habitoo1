- Partner offers use authenticated, counted server pagination with global ordering and agency filtering before pagination; agency logos use private signed storage and display preferences are user-scoped. Why: flat views must include all eligible offers rather than sort/filter a truncated first batch; proposal flows remain unchanged.
- Partner-offer handler mocks run with `vitest.partner-offers.config.ts`. Why: isolate read-query tests from the application's server-function transport transform.
- Private-listing handler mocks run with `vitest.private-listings.config.ts`. Why: test source filtering through the real handler without the server-function RPC transform.
- Company data comes from ANAF only via `src/lib/company-lookup.ts` (pure, injected fetch) with 24h `company_lookup_cache`; org sync fills empty fields only. Why: ANAF rate limit; user edits win.
- Subscription requests use transactional authenticated RPCs, organization locks, a pending-only unique index and atomic notifications; approval calls set_organization_subscription. A profile-and-role helper scopes suspended admins without current_org. Why: renewal stays available without opening CRM access or duplicating activation.
- Subscription request emails synchronously use the registered managed template and the platform contact inbox; outcomes are existing audit events read only for RLS-visible request IDs. Why: show durable send evidence without an email queue or new email tables.
- ACP market matching canonicalizes property types (`normalizePropertyType`: apartment/studio/penthouse/duplex → apartament, house/villa → casă, etc.) and treats any „București Sector(ul) N" city as București + sector N (`marketPoolScope`); the neighborhood never hard-filters ACP candidates (it only raises the location score), and below `MARKET_SECTOR_MIN_MATCHES` (8) sector matches the search widens to the whole city — in comparables collection and in the analysis „Piața" block (`expandSector: true`), but not in the user-driven Market Data Center. Why: CRM types are English, market offers are Romanian, and sector pools are often too small.
- Private listings "newest" sort uses first_seen_at (set at insert via DB default, never updated on reimport) and a two-phase query: filtered id/source/date rows are interleaved round-robin across sources within each UTC day (interleaveNewest), then the page rows are fetched by id; price/surface sorts stay single-query. Why: scraped_at changes on every reimport and sources arrive in batches, so plain ordering made the list look single-source.
- Private listings filters are a draft applied only on Căutare/Enter (URL stays the source of truth; legacy oras/zona/sursa/tip links still work); category tabs map to Romanian property_type patterns, "Zile în piață" filters first_seen_at by Europe/Bucharest day start, floor ranges use the generated floor_num column (Parter = 0), and year ranges include NULL year_built unless the checkbox is unchecked. Why: mirrors the Imobiliare.ro PRO filter model without storing owner phones or unsupported data.
- Private listings location filters: Județ/Localitate use SearchableSelect (diacritic-insensitive search, counts), Zonă opens ZonePickerDialog (search, A–Z jump, "Toate zonele", Bucharest grouped by sector — a neighborhood belongs to the sector where it appears most; sector selection includes no-neighborhood listings via zone_key.in). URL `zona` is a string array; legacy single-string links still parse. Why: mirrors the Imobiliare.ro PRO "Alege zone" model with multi-zone OR filtering.
- Private listings store owner phones only for source `anuntul` (Anuntul.ro); every other source keeps phone null at import, and the phone shows as a tel: link on the card and detail page only when present. Why: Anuntul.ro phones are provided for contact; all other sources stay phone-free.
- Argus integration (step 1, connection only): per-agency API keys live encrypted in `argus_connections` (RLS with no policies — server-only reads via supabaseAdmin after an `is_org_admin` check); the browser only ever sees `last4`. The Habitoo application token is the `ARGUS_APPLICATION_TOKEN` secret, read inside handlers. The authorization token is cached per agency and refreshed only on 401; local throttles mirror the documented limits (/auth 5/hour; data 2/s, 60/min, 600/hour), 429 waits and retries once, 403 maps to the monthly-quota message. Argus listings are never stored in the database. Why: keys and tokens must never reach the browser, and one agency must never use another agency's key.
- Argus search tab (step 2): `src/lib/argus/search.shared.ts` holds the client-safe DTOs and pure translators (UI filters → Argus body, response normalization); `search.server.ts` does the network calls through `argusCall`. Phone numbers are stripped at normalization and only `getArgusListingContact` may call `/properties/contact` (on "Arată telefon" click); search/detail never do. Repeated identical searches are served from a 5-minute TanStack Query cache (`ARGUS_CACHE_MS`). Argus listings are never stored in the database. Why: protect the monthly quota and keep owner phone data out of Habitoo storage.
