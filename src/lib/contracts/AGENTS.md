- ID scanning has one path: `IdScanPanel` → `scanContactIdentity` → `runIdentityScan` (injected deps, scope via `resolveScanScope`, one hourly per-user bucket, independent of agency AI settings), used on the contact page and in "Document nou". No storage/DB writes except an action-only audit; saving happens only via `saveContactIdentity` on confirmation or at contract creation. Why: ID images stay in request memory and nothing is persisted unconfirmed.
- Contract creation builds C5 payloads via `buildC5Request` and template variables via shared `contractTemplateVars`; for every kind, `mergeStoredIdentity` lets dialog values win and stored identities fill only empty fields, and scanned parties linked to a CRM contact are saved back via `saveIdentitiesAfterCreate`, whose failure returns a warning instead of failing the created contract. Why: tests exercise the same mapping as the handler, manual corrections are never overwritten, and agents never create a contract twice.
- The GDPR notice is a `gdpr_notice` template (agency copy wins, deleting it restores the standard); `createContract` saves its rendered text in `data.gdprNotice` for commission/viewing/exclusive kinds and the PDF appends it via `gdprNoticeForDocument` (attach recomputed from parties until signing starts, then frozen); ID values are never rendered into it. Why: existing contracts never change with template edits and the notice never shows identity numbers.
