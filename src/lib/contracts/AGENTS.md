- Contact ID scanning (C4) runs only through `scanContactIdentity` → `runIdentityScan` (injected deps, no storage/DB writes except an action-only audit); saving happens only via `saveContactIdentity` on explicit confirmation. Why: ID images stay in request memory and nothing is persisted unconfirmed.
- C5 commission/loan/viewing creation builds its payload via `buildC5Request` and template variables via shared `contractTemplateVars`; stored identities fill parties server-side unless a dialog scan is saved back to `contact_identities` at creation. Why: tests exercise the same mapping as the handler and identities persist only with a created contract.
