- Chrome extension tokens (`hbext_`) are stored only as SHA-256 hashes in `extension_tokens`; every API request re-checks token, user `is_active` and agency status via `serveExtension`, rate-limited 60/min by `extension_rate_take`. The token reaches the extension only through same-origin `postMessage` after a valid nonce and is never rendered or logged. Why: no copied keys, instant invalidation on deactivation/suspension.
- Extension captures create drafts only through the service-role RPC `extension_create_property` (idempotency per user+key, owner contact deduplicated by `ro_phone_key` within the agency, history activity); capture provenance lives only in `property_capture_sources`, never on `properties`. Why: atomic retries and source URLs can't leak into feeds, portals, PDFs, agency sites or Partner API.
