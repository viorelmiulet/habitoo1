- Primary Market OAuth uses a separate encrypted storia_developer connection and account-bound OAuth state with the existing OLX application; never register it as another listing portal. Why: agency and developer tokens must not mix.
- Investment jobs share the armed portal worker, with one running job per development; verified lifecycle success queues selected units using the same developer account, and old agency UUIDs retire only after replacement-unit activation. Why: asynchronous parent validation and safe account migration.
- Investment mandatory attributes come from reference/investments-taxonomy.json; never infer missing required values or emit unsupported URNs. Why: the current Storia taxonomy differs from documentation examples.
- Storia floor plan: at most one property_images.is_floor_plan per property (unique partial index + trigger clears the old one, cover cannot be marked); only the Storia mapper sends it as top-level floor_plan and drops it from images; other portals/feeds treat it as a normal photo. Why: OLX RE API field, no impact elsewhere.
- Storia movie_url/virtual_walk come only from properties.video_url/virtual_tour_url validated by src/lib/property-media/links.ts (https, allowed hosts, no shortlinks); invalid links are omitted with a warning, never block. Why: OLX RE API rules; other portals unchanged.
- Storia contact.photo uses only the existing /api/public/sites/v1/media/agent/{profileId}?w=400&h=400&fit=cover (storiaAgentPhotoUrl omits hidden/inactive/no-photo agents; 400×400 transform stays well under 1 MB); agency adverts, units and investments share it. Why: private avatars bucket, Storia size limits.
- Storia hide-price: developments.storia_hide_price sends urn:concept:hide-price on the investment; units get it only when the taxonomy snapshot lists it for their category; agency adverts never. Why: OLX RE API hidden-price rules.
